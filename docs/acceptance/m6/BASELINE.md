# M6.1 · 骞言碎语整站性能基线

本报告保留测试提交下的历史读数。PR #10 随后修复了评论自动加载，当前版本在评论区接近视口时触发，首屏已达到阈值的短文也会产生 Giscus 请求。复测工具会标记测量步骤前已开始的加载，这类样本没有滚动到就绪的完整计时。

## 结论

- **中文字体是冷读最重的资源。** 正式移动限速下，首页发出 18 个 WOFF2 请求、传输 545,248 B。隔离无图长随笔发出 32 个请求、传输 1,368,950 B。相同会话刷新后，首页 WOFF2 中位传输为 0 B。先评估字体覆盖与体积，再评估首屏图片调度。
- **主线程与异步功能分别验收。** 首屏导航期间没有观察到 50 ms 以上的主文档任务，搜索首次打开、搜索结果和评论就绪仍有独立的网络等待。常规 Chrome 导航的最大 CLS 为 0.0226。
- **保留两类网络异常。** 首页移动限速冷读有一条约 15.28 s 的 TTFB，等待发生在连接建立前。Giscus 部分 WOFF2 得到缺少 CORS 响应头的 HTTP 200，评论仍可进入就绪状态。两类现象的优先级和复验方法见 [瓶颈分析](BOTTLENECKS.md)。

### LCP 和关键请求链

- **生产卡片及分类。** 两个移动限速组的 5/5 次 LCP 均为共享占位封面 WebP。HTML 同时发现外链站点 CSS 和字体 `faces.css`。后者引出多条 `VeryHigh` 的 WOFF2；封面起始 `Low`，进入布局后提升为 `High`。样本中封面网络体积约 7 KB，后续实验应分别验证发现时间与优先级对 LCP 的影响。桌面原生首页的 5/5 次 LCP 为文案段落，策略需按视口判断。
- **标题列表与正文。** 移动限速标题列表和无图短文的 LCP 是文字。有图短文在同档位的最终 LCP 为正文 WebP。隔离技术稿较常见的 LCP 是 H1。LCP 可以早于最慢的字体完成，字体字节降幅无法直接折算成同等 LCP 改善。
- **脚本。** 正式 URL 还加载 Cloudflare 分析脚本与 RUM 上报；本地静态页的差值包含这类线上注入、远程 RTT 和不同内容。正式首页冷读的主文档 ScriptDuration 中位为桌面原生 6.36 ms、移动限速 19.88 ms。无图正文无图片委托入口。有图正文仅加载委托入口，灯箱核心延后至点击。 [Chrome 逐请求](metrics/chrome-production-navigation.jsonl.gz) · [Lighthouse 指标与关键链审计](metrics/lighthouse.jsonl.gz)

### 字符覆盖及分包频率

覆盖率分母为指定 DOM 文本中位于全套字体有效范围内的不同码位，分子为本次成功加载分包 cmap 的有效并集所覆盖的码位。另对视口可见文字和主区全文计算。有效范围覆盖率均为 100%，直接以采样文本里全部汉字作分母也为 100%。系统表情、代码字体和字号差异通过实际渲染抽样核对。子集利用率统计只按页面码位数量，合字、伪元素、字体 fallback 和控件文字可能引入需加载的分包，不按字符数外推可减 WOFF2 字节。

- 样本中 `3e2b50643bdf60e82d06.woff2` 在 260 次冷读均出现，文件 66,036 B，187 个有效码位，可见文本中位命中 1 个。其他每次出现的包包括 `1053336749035455c181.woff2`（39,836 B，130 个码位，可见中位命中 2 个）。低频包按样稿及字集出现，汇总 `subsets` 保存每包页面分布、命中和优先级。该排序是页面请求频率，常用字或罕见字应再以文本频次判断。
- 隔离静态站 7 个唯一路由的主区文本中，按字频取前 100 个汉字。这批字分布于 11 个已下载子集。它们在完整冷读矩阵出现 2,800 次，其余 22 个已下载子集出现 2,790 次。导航和归档文字计入语料，统计用于对照分包分布，不代表生产用户的汉字访问频次。
- 单篇长文正文首屏以外的文字也已排版。无图长随笔的分包和字节依然高于两图文章。仅改变图片加载策略无法减少这部分字体开销。
- 实际渲染样本中，页首、H1、首段稳定后可看到 `LXGWWenKai-Regular`，代码抽样使用本机等宽字体。强制延迟的两组 H1 均从 `PingFangSC-Regular` 切为文楷；本地技术稿的 CLS 约 0.0002，正式有图短文为 0.0108–0.0216。延迟 WOFF2 1.5 s 的故障注入保存了首屏 fallback 与换字后的实际字体、`loadingdone` 及具体 LayoutShift。常规矩阵保留首个和末个资源的响应结束。CSS `loadingdone` 的独立抽样和 Resource Timing 的网络完成含义不同。

## CDN 与发布

| 资源 | 只读响应观察 |
| --- | --- |
| 正式 HTML | `public, max-age=0, must-revalidate`，本轮 curl 约 6.9／9.6 KB gzip，`DYNAMIC`，两个路径未提供 ETag/Last-Modified。未强行构造无验证器的 304。 |
| Astro 哈希 CSS、JS 及评论主题 | `max-age=0, must-revalidate`。可用 ETag，重复条件 GET 返回 304，冷探测见 MISS/EXPIRED，重验见 REVALIDATED。生产浏览器的实际缓存命中另见逐请求记录。 |
| WebP、WOFF2 | `max-age=31536000, immutable`，可用 ETag 和 Last-Modified。手工条件请求返回 304。普通重访通常直接从浏览器缓存取得。CDN 见 HIT/MISS；抽查 WOFF2 HIT 的 Age 约 261,134 s。 |
| `faces.css` | `public, no-cache`，可用 ETag 和 Last-Modified，条件 GET 304，`REVALIDATED`。浏览器暖读可复用响应体，部分样本付出重验往返。 |
| Pagefind | 稳定名 `pagefind.js`、Worker、`pagefind-entry.json`、WASM 与带哈希的 fragment/index 同为 `max-age=0, must-revalidate`。样本 ETag 可产生 304。JS、JSON 见 gzip；二进制分片保留其已有编码。manifest 使用查询参数的浏览器记录与 curl 无参数探测分开。 |

HTTP 探测为 HTTP/2；浏览器响应的协议、压缩、缓存头及 Cloudflare PoP 逐条保留。304 是已发起的网络条件请求，边缘 HIT 仍可能把完整响应体传给浏览器。同版 Pagefind 1.6.0 的本地与线上 WASM 文件为 55,400／55,386 B，解包后均 126,927 B，但 WASM SHA 不同。其它抽样 Pagefind 资源与生产构建字节一致，两端检索均通过。分发验收应按实际发布产物固定 SHA，稳定文件名不能作为字节一致的证明。 [WASM 字节对照](metrics/pagefind-wasm.json)

同一版本路径更新后的风险集中在 `faces.css` 和 Pagefind 的清单、Worker 与已打开页面。长期缓存只适用于生命周期可验证的内容哈希资源。上线跨版本一致性需要对连续两版验证 HTML、索引、回退及旧资产可达性。 [头、协议、哈希和条件 GET](metrics/delivery.json)

**Giscus CORS。** 正文 Origin 加载字体成功。访客 iframe 能就绪，部分 WOFF2 在浏览器拒绝，Console 明确报缺少 `Access-Control-Allow-Origin`。对失败文件 `f04adb351d6acdd092ad.woff2` 的同 ETag HTTP/2 HIT，`Origin: https://qians.day` 有匹配头，`Origin: https://giscus.app` 无匹配头。另一抽查文件在 giscus Origin 可返回匹配头，两个对象的结果表明，该路径需要逐对象复验。确认的是边缘实际响应不一致与 iframe 回退，桶配置／缓存策略根因待 M6.5。 [同 URL 双 Origin](metrics/iframe-cors.txt) · [浏览器失败记录](metrics/chrome-production-interaction.jsonl.gz) · [Cloudflare R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/)

## 复测

在仓库根目录使用 Chrome Stable 及锁定 pnpm。保持同一机器和网络，交互和 Lighthouse 测量串行，复测某项可用 `--filter`。JSONL 逐行追加，新一轮使用新的 `--out` 目录；追加重试用 `--start-at` 避免重用编号。带 .gz 的同名证据可以直接由汇总脚本读取。

终端 A 启动隔离样稿服务器。

```sh
pnpm install --frozen-lockfile
node docs/m4.2/preview.mjs
```

另开一个终端启动生产模式的评论夹具服务器，端口 4633。

```sh
node docs/acceptance/m6/tools/preview-comments.mjs
```

终端 B 依次执行。

```sh
baseline=$(mktemp -d)
suite=docs/acceptance/m6/tools
pnpm run build
node "$suite/browser.mjs" --site=production --out="$baseline"
node "$suite/browser.mjs" --site=local --out="$baseline"
node "$suite/browser.mjs" --site=production --suite=interaction --filter='^(desktop/native|mobile/shaped)/' --out="$baseline"
node "$suite/browser.mjs" --site=local --suite=interaction --filter='^(desktop/native|mobile/shaped)/' --out="$baseline"
node "$suite/lighthouse.mjs" --out="$baseline" --reports="$baseline/reports"
node "$suite/delivery.mjs" --actions --out="$baseline"
uv run --with fonttools==4.61.1 --with brotli==1.2.0 python "$suite/font-cmaps.py" --output "$baseline/font-cmaps.json"
node "$suite/summarize.mjs" --out="$baseline"
```

`--screenshots=/absolute/path` 可保留 Chrome 代表截图，`--reports` 输出 Lighthouse HTML/trace 样本。全文查阅 [原始证据索引](metrics/) · [Ego Lite 首页](screenshots/ego-production-home.png) · [本地移动长文](screenshots/local-mobile-tech.png) · [本地移动多图](screenshots/local-mobile-life.png) · [线上搜索](screenshots/production-desktop-search.png)。
